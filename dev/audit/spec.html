1. Specs: contradições e omissões

Leitura de docs/** cruzada com schema/*.yaml. Sev: A alta, M média, B baixa.

1.1 Contradições

IDSevOndeProblema
S1Ashort-answer.md:149-226, 377-388
schema/short-answer.yaml:16-36		 Spec diz que [short-answer]: X equivale a ser o único item de accept. Schema e exemplos gravam em oneOf (literal) ou regex (/.../). oneOf, regex e openEnded não aparecem na tabela de frontmatter nem em nenhuma seção de prosa, só na tabela de regras. A forma de lista ([short-answer]: + ul, exemplo short-answer/list) não existe na gramática. Parte já registrada em dev/issues/lint-spec-open-decisions.md.
S2Amultiple-choice.md:102-103 vs 174-200 "an omitted value is 0" contra a seção Grading, que trata valor omitido como "unspecified" (_) e deriva score negativo em symmetric. Os exemplos gravam score: 0 para [ ], então o AST vindo de markdown não distingue [ ] de [0%] e symmetric nunca penaliza. examples/grading/multiple-choice.yaml distingue null de 0.0. Schema permite omitir score.
S3Amultiple-choice.md:196 Tabela de grading: linha [1, 1, _, _] symmetric = -0.50. Pela regra (média zero) é -1.00: 2 + 2x = 0. A linha seguinte [1, 0.5, _, _] = -0.75 segue a regra, então a linha 2 está errada.
S4Aexam.md:275-278 vs multiple-selection.md:96-106 "Under the default none, symmetric and partial produce identical exam totals" é falso. [T, F, _, _] dá 0.75 em partial e 0.5 em symmetric, ambos positivos. O piso em 0 só iguala os casos negativos.
S5Afill-in.md:170-172, 206-215 vs 221-225 "only choice blanks can carry [feedback] ... short answer blanks have no feedback syntax" contra pattern_item "including its > feedback and ! comment lines" e o exemplo do planeta, que tem feedback em blank short-answer.
S6Mresponses.md:129-136 Unidade incompatível: "MUST reject ... with grade zero" (linha 130) contra "a unit other than the declared one" é resposta malformada, "never a wrong answer" (linha 133).
S7Mnumeric.md:70 vs 117-124 Gramática só permite abstol INTEGER ou DECIMAL. A tabela de domínio tem linhas com abstol fraction. Schema: tolerance.absolute é number, então fração também não entra por YAML.
S8Mbase.md:85-88, exam.md:88-91, 310, 331 vs examples/valid/exam/scheduled "A value keeps its YAML type and is never converted" contra start: 2026-03-10 09:00:00-03:00 sem aspas (timestamp YAML, separador espaço, não é ISO 8601), aceito e convertido para string. Spec só cobre a exceção 1:30. Falta dizer se timestamp YAML é aceito em start.
S9Mbase.md:179-181 vs numeric.md:62, fill-in.md:92-95 base.md: tag seguida de : pode ter espaços em volta do dois-pontos. Gramáticas de numeric e fill-in não têm ws? antes do :; short-answer tem.
S10Mordering.md:268-269 vs 350 dedent: "removes the common leading whitespace" (preserva indentação relativa) contra "reducing every line to indentation level 0". São duas semânticas diferentes na mesma frase.
S11Mshort-answer.md:220-226 [short-answer] pode ser combinado com [short-answer/accept], mas é interpretado "as if its content were the only pattern of the accept block". Não diz como os dois se combinam nem a ordem, que importa para feedback.
S12Mschema/exam.yaml:24-25, schema/question-base.yaml (id) Descrições desatualizadas: "A number written in the frontmatter is read as its decimal string form" contra exam.md:88-91 (nunca converte). id de questão: "may be derived from position or title".
S13Bbase.md:103-104 vs 275 Reticências no stem: recurso oferecido (implementação MAY expandir) e ao mesmo tempo lint info pedindo para o autor não usar. Não define se o AST guarda ... ou o texto expandido. lint-codes aceita … (U+2026); base.md não menciona.
S14Bbase.md:224-225 vs ordering.md:124-128 "all fields in the frontmatter are translated as-is" contra tags string virar lista (só dito de passagem em ordering.md). Não define trim dos itens após o split.
S15Bbase.md:278-280 Nota 8 cita "the locale pattern in Frontmatter". Não existe pattern nessa seção nem no schema.
S16Bshort-answer.md:382 "accept, reject, oneOf: each body block may be defined at most once". oneOf não é bloco do corpo.
S17Bnumeric.md:11, essay.md:10 Exemplos com espaço no fim da linha (1000 , [essay] ) que as gramáticas não aceitam.

1.2 Omissões

IDSevOndeProblema
O1Abase.md:65, docs/question-types/* Inferência de tipo não especificada. Lista só com [ ]: multiple-choice ou multiple-selection? O exemplo multiple-selection/none-correct infere multiple-selection, regra que só existe no comentário do YAML. Também indefinido: marcadores misturados ([*] com [x], [T] com [ ], [50%] com [x]).
O2Aschema/exam.yaml:178-187 Entry do exame não inclui ordering.yaml. Exame com questão de ordenação falha no schema. exam.md:296-300 também não lista ordering (coerente, grading é binário), mas a questão em si deveria ser aceita.
O3Atodos os tipos Mapeamento markdown para AST não está em prosa na maioria dos tipos. Campos que só aparecem no schema ou nas tabelas de regras: choices[].score/correct, answer, tolerance.absolute/relative, lines, extra, accept/reject (ordering), blanks[], answerKey, comment (comment string), instructions e questions (exam), forma do bloco include no AST.
O4Mbase.md:140-166, multiple-choice.md:36-49, 61 Gramática de parse do slug e do [choice-id] não definida. O regex é SHOULD, então não diz o que conta como slug. [link](url) texto no primeiro parágrafo ou no início de uma choice: slug ou link? A gramática de item nem tem o [choice-id].
O5Mexam.md, base.md:79 Fórmula da nota do exame só aparece numa nota de rodapé de base.md ("weighted mean"). exam.md não define: média ponderada, questões pendentes de correção manual, soma de pesos igual a 0.
O6Mshort-answer.md:13-15 vs grammar.md:11-23 Normalização usa /\s+/, a classe que grammar.md proíbe por divergir entre Python e JS (U+FEFF, U+0085, U+001C-1F). Também não define o algoritmo de case folding (lower vs casefold) nem o de remoção de diacríticos (ø, ß, đ).
O7Mshort-answer.md:231-255 Literal que começa com / não tem escape. /usr/bin é lido como regex usr com flags b, i, n, todas válidas. Só sobra a forma exata com crases. Falta também o que fazer com flag desconhecida e flag repetida.
O8Mexam.md:134-138, 356; lint-codes.md Regra crítica "epilogue must not use --- as thematic break" não tem código de erro e não diz como o parser detecta. O exemplo exam/thematic-break-in-question usa --- no preâmbulo; a regra só cita o epílogo. Falta definir --- seguido de texto que não é mapping YAML.
O9Mlint-codes.md vs tabelas de regras Regras críticas sem código: fill-in "at most one of each form"; ordering "at most one extra", "same content block type", "at most one feedback and one comment block"; short-answer "each body block at most once". Se são parse-error, o spec deve dizer. Outras já estão em lint-spec-open-decisions.md.
O10Mnumeric.md:24, responses.md:135 decimalPlaces sem semântica: arredonda a resposta, valida a entrada, é inferido do número de casas do answer? O lint ignored-decimal-places-inferred sugere inferência que o spec não descreve.
O11Mordering.md:236-260, 295-301; responses.md:186-187 Em fixed o nível é ignorado na correção, mas "same text and same level are the same line". Duas linhas com mesmo texto e níveis diferentes ficam indistinguíveis na correção. Nível de indentação para conteúdo ul (lista aninhada?) não definido.
O12Mfill-in.md:39-80, base.md:129-137 Blank fora do stem: [^id] em preâmbulo ou epílogo é blank, texto ou erro? O stem é um parágrafo só. Já existe dev/issues/blank-placement.md.
O13Bexam.md:322-338 Gramática de duração aceita string vazia, P e PT (a prosa proíbe). Forma canônica ambígua para semanas: P7D vira P1W? Forma canônica de start só com data não definida.
O14Bexam.md:126-132 --- logo após parágrafo é setext H2 em CommonMark. O spec exige linha em branco antes de ===, mas não antes do --- de um bloco.
O15Bexam.md:200-229 Questão do banco sem id selecionada por include-all: não diz se entra, nem com que id.
O16Bessay.md:21, true-false.md:143-157 Default de input não definido. Letras esperadas por locale não definidas (a tabela de referência só tem as palavras), então locale-mismatched-true-false-marker varia por implementação.
O17Btrue-false.md:79-90 PROVISIONAL significa true. Toda inicial nativa de "falso" fora da lista é lida como true: Н (ru), अ (hi), ম (bn), خ (ar), ج (ur). Só S em id tem aviso dedicado; os outros caem no aviso genérico de PROVISIONAL. A justificativa do S usa romanização.
O18Bbase.md:87-88 null só é definido para id e tags. Demais campos (title: vazio) sem regra.
O19Abase.md:85-88, exam.md:88-91, 331 Versão do YAML e resolução de escalares não definidas. O spec depende de YAML 1.1 para include: yes ser booleano (erro) e para o timestamp de start, mas rejeita YAML 1.1 para 1:30. Um parser YAML 1.2 (default em JS) lê yes como string e aceita invalid/exam-ids-not-strings. Achado do agente de exam.
O20Mexam.md:247-260 Não diz se o AST mostra locale/author herdados. Os exemplos mostram. Ids derivados têm o tratamento oposto (fora do AST).
O21Mbase.md:78, 265 vs lint-codes.md:85 locale: base.md diz "valid", lint-codes diz "well-formed". São termos distintos na RFC 5646 (ver M24).
O22Mbase.md:270 vs schema (minLength: 1) title: "" é erro de schema; title: " " é warning. A prosa só tem a regra de warning. Mesmo para author, description, course. "Pelo menos 2 choices" também só existe no schema.
O23Mfill-in.md:197-199 vs schema/fill-in.yaml Blank short-answer aberto é válido na prosa e não tem forma no AST: o schema do blank não tem openEnded.
