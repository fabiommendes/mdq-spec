Proposed public surface

ModuleNames
mdqload, parse, Loaded, Diagnostic, Severity, Question, Exam, QuestionBank, FileLoader, DictLoader, MdqError, InvalidDocument
mdq.modelsevery document-tree class (question types, choices, blanks, Include, IncludeAll, Exam, QuestionScore). No helpers.

mdq.clinot API: app, main only.

Everything else becomes _private or leaves the wheel (tests/scripts).

Findings

  • F1 str(exam) / Exam.render() raise NotImplementedError (verified on examples/valid/exam/*).
  • F2 Exam.resolve needs a QuestionBank, but banks are not exported from mdq. It also raises ParseError / pydantic ValidationError directly, outside the Diagnostic pipeline.
  • F3 mdq.ParseError is exported, but load/parse never raise it (converted to Diagnostic).
  • F4 mdq.hypothesis ships in the wheel and imports hypothesis, which is only a dev dependency.
  • F5 testing.py, scripts/, converter strategies ship in the wheel but only work inside this repo (read root examples/, docs/).
  • F6 loading vs loaders: names differ by one letter, roles unrelated (pipeline vs question banks).
  • F7 Duplicates: QUESTION_TYPES x3; Literal aliases in types and models; COMMON_QUESTION_KEYS in parser and hypothesis.
  • F8 Dead: ExamScore, Exam.add_question, errors.{ValidationError, MissingIdError, EmptyQuestions, NodesRemaining}, testing.lint_json_sibling, hypothesis.documents.md_tables, ~12 aliases in types.
  • F9 Stale docstrings: MdqModel.__str__/render mention mdq.render.render().
  • F10 docs/api has one page per module (25), incl. helpers. Surface in docs = surface of the package.

Rules the layout enforces

  • R1 A _module is imported only by its parent package or its siblings. Exception listed in the plan: cli._show uses models._render.
  • R2 Public modules: mdq, models, types, errors, convert, hypothesis. Docs pages = these 6 (+ CLI reference).
  • R3 Nothing in the wheel reads the repo layout (examples/, docs/).
  • R4 models/_*.py by question family mirrors docs/question-types/*.
