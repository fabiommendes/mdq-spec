# Lint diagnostic codes

Reference list of every `code` the lint pass can report. Most codes report
`warning` or `info` severity; an `error` code prevents the question or exam
from being processed at all -- see the "Errors" table below.

The rules are derived from the `mdq` references at [exam.md] and all files at
[question-types]. They apply both to mdq-py and mdq-js. In the "Question
types" column, "any" includes exams.

| Code                                   | Severity | Question types                                           | Description                                                                                                                                                                                           |
| -------------------------------------- | -------- | -------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accept-repeats-answer-key`            | warning  | ordering                                                 | An `accept` entry holds the same lines as the `[ordering]` block itself, once fully normalized.                                                                                                       |
| `all-choices-correct`                  | info     | multiple-choice, multiple-selection, fill-in             | Every choice is correct (or has a `score` of 1), so the question has no wrong answer.                                                                                                                 |
| `answer-outside-domain`                | warning  | numeric, fill-in                                         | `domain` is `integer` and the answer is not a whole number, or `domain` is `fraction` and the answer is neither a whole number nor a fraction string (`0.75`, `"0.75"`). A string answer is judged by its value (`"7/2"`). |
| `blank-ordering-line`                  | info     | ordering                                                 | A `lines`/`extra` entry is blank, and `skip-blanks` is not normalized, so it counts when comparing a response.                                                                                        |
| `case-variant-blank-id`                | warning  | fill-in                                                  | Two blank ids differ only in ASCII case, such as `[^rio]` and `[^RIO]`. Blank ids are case-sensitive, but CommonMark labels are not.                                                                  |
| `code-content-without-highlight`       | info     | essay, ordering                                          | `content: code` is set but no `highlight` language is given.                                                                                                                                          |
| `domain-mismatch`                      | info     | numeric, fill-in                                         | The declared `domain` is `integer` or `fraction`, and the absolute tolerance is a decimal (numeric.md, "Additional Rules"). |
| `duplicate-alternative-lines`          | warning  | ordering                                                 | Two `accept` entries, or two `reject` entries, hold the same lines, once fully normalized.                                                                                                            |
| `empty-include-all`                    | warning  | exam                                                     | An `includeAll` adds no question: nothing matches its query, every match is already in the exam, or the query cannot be read. Reported by `Exam.resolve`, not by `load`.                                                       |
| `exam-without-questions`               | warning  | exam                                                     | The exam has no questions, so it cannot be answered.                                                                                                                                                  |
| `false-friend-true-false-marker`       | warning  | true-false                                               | The marker is a false friend of the `locale` row: it reads as true, but it is a letter for false in that language (`S` under `id`, `B` under `bn`). The row table decides (true-false.md, "Locale").  |
| `ignored-decimal-places`               | info     | numeric, fill-in                                         | `decimalPlaces` is set, but the domain (declared, or inferred from the answer and the absolute tolerance) is not `decimal`.                                                                           |
| `ignored-regex-flag`                   | info     | short-answer, fill-in                                    | A `/.../flags` pattern (a delimited `accept`/`reject`/`preAccept`/`preReject` entry) carries a flag that is accepted but has no effect. One diagnostic per pattern, not per flag.                                                                           |
| `locale-lookalike-language`            | info     | any                                                      | `locale`'s language subtag is a two-letter code that looks like a country code rather than a language (e.g. `cn` instead of `zh`).                                                                    |
| `locale-mismatched-true-false-marker`  | warning  | true-false                                               | A TRUE or FALSE letter is not `T`/`F` and not accepted by the `locale` row (true-false.md, "Locale"). `T`/`F` never get it.                                                                                                            |
| `malformed-separator`                  | warning  | exam                                                     | A line that holds only `=`, spaces and tabs, with at least three `=`, and is not a `===` separator (`====`, `   ===`, `= = =`). It is text, so the questions after it are read as part of the text before it (exam.md, "Question and include blocks"). |
| `many-correct-choices`                 | info     | multiple-choice, fill-in                                 | More than one choice has a `score` of 1. A question MAY mark any number of choices as correct; this only flags the unusual case.                                                                                                                                                     |
| `missing-answer-key`                   | info     | essay                                                    | `answerKey` is not defined.                                                                                                                                                                           |
| `missing-choice-id`                    | info     | multiple-choice, multiple-selection, true-false, fill-in | A choice declares no `id` of its own; one will be derived from its text.                                                                                                                              |
| `missing-id`                           | info     | any                                                      | `id` is not defined.                                                                                                                                                                                  |
| `missing-title`                        | info     | any                                                      | `title` is not defined.                                                                                                                                                                               |
| `missing-tolerance`                    | info     | numeric, fill-in                                         | No `tolerance` is given and `domain` (declared, or inferred) is `decimal`, so only an exact match is accepted. A `fraction` or `integer` question has no such diagnostic. |
| `multi-line-pattern`                   | warning  | short-answer, fill-in                                    | An exact literal or a regex in the Markdown body spans more than one line. Each line ending becomes a U+0020 that is part of the pattern, so write it on one line. An inexact literal has no such diagnostic. YAML, JSON and frontmatter patterns have no line endings. |
| `no-correct-answer`                    | warning  | short-answer, fill-in                                    | No response can be correct: the question (or short answer blank) has no `accept` pattern and `unmatched` is `incorrect`.                                                              |
| `no-correct-choice`                    | info     | multiple-choice, multiple-selection, fill-in             | No choice is correct (in multiple choice and fill-in, no choice has a `score` of 1), so the question has no right answer.                                                                                                                                                            |
| `non-ascii-whitespace`                 | warning  | any                                                      | A Unicode space (a `White_Space` character outside ASCII, or U+FEFF after the start of the file) outside code. U+0085, U+2028, U+2029 and a space in a syntax position report this code; any other space in prose reports `non-ascii-whitespace-in-prose`. See [grammar.md].         |
| `non-ascii-whitespace-in-prose`        | info    | any                                                      | A Unicode space in prose that is not U+0085, U+2028 or U+2029 and not in a syntax position. See [grammar.md] for the positions.                                                                                                                                                      |
| `non-nfkc-true-false-marker`           | info     | true-false                                               | The marker is a valid letter, but not its own NFKC form.                                                                                                                                             |
| `nonstandard-include-query`            | warning  | exam                                                     | An `includeAll` query does not follow the query language docs/exam.md recommends. `Exam.resolve` adds no questions for it.                                                                           |
| `redundant-id`                         | warning  | any                                                      | `id` is set both in the frontmatter and as a slug. The frontmatter value wins, whether the two values are equal or not.                                                                                        |
| `redundant-regex-anchor`               | info     | short-answer, fill-in                                    | A delimited `accept`/`reject`/`preAccept`/`preReject` entry writes an anchor that is already implicit: `^` without the `f` flag, `$` without the `f` or `b` flag.                                              |
| `redundant-strict-indentation`         | warning  | ordering                                                 | `indentation: "strict"` is set, but `dedent` is normalized, which flattens every line to level 0.                                                                                                     |
| `reject-without-feedback`              | info     | ordering                                                 | A `reject` entry declares no feedback. It still scores its ordering 0, which settles a response under `unmatched: manual`.                                                                           |
| `relative-tolerance-around-zero`       | warning  | numeric, fill-in                                         | A relative tolerance around an answer whose value is `0` (`0`, `"0.0"`, `"0/5"`) can never widen the accepted range.                                                                                  |
| `relative-tolerance-over-one`          | info     | numeric, fill-in                                         | A relative tolerance is greater than `1`: it is stored as a fraction, so in YAML or JSON it is likely a percentage written by mistake, and in every form a tolerance above 100% accepts responses of the opposite sign.                                                                                           |
| `separator-before-include`             | warning  | exam                                                     | An include block (`include` or `includeAll`) is preceded by a `===` separator, which it does not need.                                                                                               |
| `setext-heading`                       | warning  | exam                                                     | A `---` or `===` line right after text is a setext heading, not a block boundary. Put a blank line before the `---` that opens a block.                                                              |
| `stray-choice-marker`                  | warning  | any (`stem`, `epilogue`)                                | An unordered list outside the body has some items, not all, that start with a choice marker whose value belongs to a choice type (`[ ]`, `[x]`, `[*]`, a percentage, a letter) or is empty (`[]`). It is almost always a broken choice list (question-base.md, "Forbidden elements").|
| `undeclared-id-after-include-all`      | warning  | exam                                                     | An inline question after an `includeAll` declares no `id`, so its derived id changes with the questions the query adds.                                                                              |
| `uniform-true-false-answers`           | info     | true-false                                               | Every statement is true, or every statement is false, so there is nothing to distinguish by judgement.                                                                                                |
| `unknown-highlight-language`           | info     | essay, ordering                                          | `highlight` is not a recognized alias of a Pygments lexer.                                                                                                                                            |
| `unlisted-true-false-marker`           | warning  | true-false                                               | The marker is a WARNING letter that its `locale` row does not accept: it is in neither the TRUE nor the FALSE list, and reads as true.                                                                                                  |
| `unmatchable-regex-escape`             | info     | short-answer, fill-in                                    | Under the `n` flag, a `/.../flags` pattern has an escape (`\uXXXX`, `\xXX`, `\u{...}`) for a code point that the diacritics strip changes, so the stripped response cannot contain it. One diagnostic per pattern. |
| `unreachable-alternative`              | warning  | ordering                                                 | A `reject` entry uses a line, or more copies of a line, than `lines` and `extra` offer together, once fully normalized, so no response can match it.                                                  |
| `unsafe-id`                            | warning  | any                                                      | `id` is not url-safe (`[a-zA-Z0-9]+(?:[-_][a-zA-Z0-9]+)*`).                                                                                                                                           |
| `unsafe-thematic-break`                | warning  | any (`stem`, `epilogue`, `answerKey`, `extra`, `accept`, `reject`) | A thematic break written with `-` (`---`, `- - -`, ...). Inside an exam a `---` line opens a block, so the break changes meaning when the text is pasted into one. Write `***` or `___` instead (exam.md, "Question and include blocks"). |
| `unsplit-tag-list`                     | warning  | any                                                      | A `tags` entry contains a comma; comma-splitting only applies when `tags` is written as a single string.                                                                                              |
| `uuid-unknown-variant`                 | warning  | any                                                      | The UUID's variant nibble is not one of `8`, `9`, `a`, `b`.                                                                                                                                           |
| `uuid-unknown-version`                 | warning  | any                                                      | The UUID's version nibble is not one of `1`-`8`.                                                                                                                                                      |
| `visually-identical-choices`           | info     | multiple-choice, multiple-selection, true-false, fill-in | A choice's text renders the same as another's but is written differently in source.                                                                                                                   |
| `visually-identical-lines`             | info     | ordering                                                 | Two `lines`/`extra` entries render alike but differ in raw source; a student ordering the rendered text cannot tell them apart.                                                                       |

## Errors

These error codes prevent a question/exam object from being loaded. They do not
include parser errors, and must be checked manually either by the parser (at
some post-processing stage) or by the model validator (pydantic or zod).

| Code                                       | Question types                                                     | Description                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ------------------------------------------ | ------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `accept-outside-answer-key`                | ordering                                                           | An `accept` entry holds a line the `[ordering]` block lacks, or more copies of a line than it has, once fully normalized.                                                                                                                                                                                                                                                                                                                                                                                      |
| `accept-reject-overlap`                    | ordering                                                           | An `accept` entry, or the `[ordering]` block itself, holds the same lines as a `reject` entry, once fully normalized.                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `blank-text`                               | any                                                                | A free-text field is defined but empty or has no visible character: `title`, `author`, `comment`, `description`, `course`, the `unit` of a numeric question or blank, `stem`, `epilogue`, `instructions`, `answerKey`, `incorrectFeedback`, and the `text`, `feedback` and `comment` of a choice, an ordering alternative or a pattern. Also a pattern string with no visible character (`"   "`, an exact literal of one space, a lone U+200B); an empty pattern string is a `schema-error`. For `comment`, only YAML and JSON input: a Markdown comment string with no visible character is not stored. Also an entry of `tags`; the empty part after a final comma of a `tags` string is dropped, not reported. `null` in an OPTIONAL field is an absent field; in a required field it is a `schema-error`.                                                  |
| `block-start-pattern`                      | short-answer, fill-in                                              | An inexact pattern string starts a CommonMark block other than a paragraph: a block quote, an ATX heading, a list item, a fenced code block, an HTML block or a thematic break (`# Brasília`, `> x`, `- x`, a lone `*`). Write an exact literal (`` `# Brasília` ``) or a regex. In a pattern item of the Markdown body the error is a `parse-error`, see [Pattern string](references/patterns.md#pattern-string). |
| `detached-tag`                             | any                                                               | A known tag is in the epilogue, outside fenced code, because a block that is not a tag came before it: a `[short-answer/reject]:` after a paragraph, a second `[numeric]:`, a blank definition such as `[^capital/short-answer]: Brasília` after a block that is not a definition, a line of a fill-in epilogue that starts with `[^slug]:` (with or without a kind suffix and with or without text after the colon), or an `[ordering]:` or `[essay]` tag. The message tells the author to move the tag up, before the epilogue. The stem reference of a blank id gives no `undefined-blank` (question-base.md, "Body tags"). |
| `duplicate-blank-id`                       | fill-in                                                            | Two blanks declare the same `id`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `duplicate-blank-reference`                | fill-in                                                            | A blank id appears more than once as a `[^id]` marker in the stem.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `duplicate-choice-id`                      | multiple-choice, multiple-selection, true-false, fill-in           | Two choices (or one choice blank's choices) declare the same `id`.                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `duplicate-choice-text`                    | multiple-choice, multiple-selection, true-false, fill-in           | Two choices' texts are the same once whitespace is normalized outside code spans.                                                                                                                                                                                                                                                                                                                                                                                                                              |
| `duplicate-question-id`                    | exam                                                               | Two entries of `questions` -- inline or `include` -- resolve to the same id, a declared one or the derived id (`q1`, `q2`, ...) a question with none would get.                                                                                                                                                                                                                                                                                                                                                |
| `empty-ordering-answer`                    | ordering                                                           | The `[ordering]` block, or an `## [accept]` entry, holds no line after normalization (for example a code block of only blank lines under `skip-blanks`). An empty `reject` entry is valid. |
| `empty-ordering-line`                      | ordering                                                           | With `content: text`, a line of `lines`, `extra`, `accept` or `reject` has empty text. Only a code block holds a blank line. |
| `forbidden-block-element`                  | any (`stem`, `epilogue`, and an exam's `instructions`)             | The field holds an H1 heading, a heading starting with `[`, a paragraph starting with `[` (except the very first paragraph of the stem, or when the `[` is immediately followed by `^`, the fill-in blank-marker syntax), or an unordered list whose items all start with `[` -- one of question-base.md's "Forbidden elements", which could be mistaken for the question body. A `[` that starts a markdown link (`[text](url)`, `[text][ref]`) does not count. Checked at the model level, so a `dict`/YAML/JSON document is covered too, not only one built from Markdown. |
| `foreign-choice-marker`                    | multiple-choice, multiple-selection, true-false, fill-in, essay    | A choice value is not in the `value` rule of the question type, inferred or forced by `type` (question-base.md, "Type inference"): `[x]` in a multiple choice list, `[ ]` in a true/false list, `[*]` in a list forced to multiple selection, `[?]` anywhere. | `invalid-duration`                         | exam                                                               | `duration` is not a positive duration in one of the accepted forms (exam.md, "Duration and Start Time"): an ISO 8601 duration with fixed-length units, `HH:MM` or `Xd Yh Zm`. | `invalid-frontmatter-field`                | any                                                                | A key of the frontmatter is not a field of the frontmatter table of the question type or of the base table: a field that the body sets (`stem`, `choices`, `accept`, the `unit` of a numeric question, ...) or an unknown key. | `invalid-outline-level`                    | ordering                                                           | With `content: text`, a block holds a first line above level 0, or a line more than one level deeper than the previous one. Applies to `lines` and to each `accept` and `reject` entry, not to `extra`.                                                                                                                                                                                                                                                                                                        |
| `invalid-regex`                            | short-answer, fill-in                                              | A `/`-delimited pattern in `accept`/`reject`/`preAccept`/`preReject` does not compile as an MDQ regex, or carries an unknown or repeated flag (patterns.md, "Regex" and "Regex flags").                                                                                                                                                                                                                                                                                                                                    |
| `malformed-locale`                         | any                                                                | `locale` is not a well-formed BCP 47 language tag (RFC 5646 grammar; registration is not checked).                                                                                                                                                                                                                                                                                                                                                                                                             |
| `malformed-numeric-answer`                 | numeric, fill-in                                                   | A string `answer` is not a valid `sign? numeric_value` (numeric.md, "Answer representation": an `INTEGER` or `DECIMAL` with an optional exponent, or a fraction with a nonzero denominator), or a number `answer` or tolerance is not finite (`.inf`, `.nan`), or an `answer` or tolerance is outside the range of a double (a modulus above about 1.8e308, or a nonzero value that rounds to 0). | `malformed-start`                          | exam                                                               | `start` is not an ISO 8601 date or date-time (exam.md, "Duration and Start Time").                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `malformed-true-false-marker`              | true-false                                                         | A `marker` is not a single letter (one code point in `LETTER`): it is empty, longer, has whitespace around the letter, or is not a letter (true-false.md, "Additional Rules"). `X`/`x` is `reserved-true-false-marker` instead. | `malformed-uuid`                           | any                                                                | `uuid` is not shaped like a UUID at all. | `misplaced-blank`                          | fill-in                                                            | A `[^id]` marker appears outside a plain text run of the stem -- in a heading, list item, table cell or blockquote, or inside emphasis, a strong span, link text or image alt text. Code is literal text.                                                                                                                                                                                                                                                                                                                                                                       |
| `missing-decimal-places`                   | numeric, fill-in                                                   | The answer is a fraction, the domain is `decimal` and `decimalPlaces` is not given, and the absolute tolerance is not defined or has 0 decimal places, so nothing gives the decimal places (numeric.md, "Decimal places"). |
| `reserved-true-false-marker`               | true-false                                                         | Marker `X` or `x` is reserved for a selected multiple-selection choice and has no true/false meaning. It applies to the `marker` field of model input only.                                                                                                                                                                                                                                                                                                                                                                                                          |
| `true-false-marker-disagrees-with-correct` | true-false                                                         | A marker's category contradicts `correct`: a FALSE-category marker with `correct: true`, or a TRUE- or WARNING-category marker with `correct: false` -- WARNING markers represent true (true-false.md, "Body"), so they contradict `correct: false` too.                                                                                                                                                                                                                                                       |

## Load errors

These codes are not rules about the document content. `load` reports them
when it cannot read the input or cannot build a model at all.

- `yaml-syntax-error`, `json-syntax-error`: the input is not valid YAML or JSON,
  or a mapping repeats a key. `yaml-syntax-error` also covers the frontmatter
  of a Markdown document or of an exam block.
- `parse-error`: the Markdown source does not follow the MDQ grammar.
- `invalid-document`: the top level of the document is not a mapping.
- `wrong-kind`: the caller asked for a question and got an exam, or the
  reverse.
- `unresolved-include-all`: ids were requested for an exam that still holds an
  `includeAll` block, which only `Exam.resolve` can expand.
- `schema-error`: the document breaks a rule of the JSON Schema that has no
  code of its own: a missing or unknown field, a value of the wrong type, a
  number out of range, a string that does not match its pattern, and so on.
  The diagnostic keeps the path and the validator's message. A rule with a
  code in the "Errors" table above reports that code instead.
